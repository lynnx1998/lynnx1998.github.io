01 · OVERVIEW

问题与出发点

INITIAL HYPOTHESIS · 初始假设

Guild Log 是一个放置互动游戏式的任务管理原型。首页同步现实任务与角色状态：当用户阅读、运动或完成生活事项时，角色也在小屋中学习、探索与成长。任务带来 EXP 和积分，积分可以购买小屋装饰与人物道具；一天的行动最终还会被写成可以回看的冒险。它试图让“完成任务”同时产生进度、拥有感与记忆。

02 · CORE LOOP

把现实行动转译成个人叙事

最终机制没有让系统自动替用户下结论，而是在完成三项任务后解锁一次主动选择：用户决定今天的叙事方向，再生成第一人称 Chronicle。

LONG-TERM LOOP · 长期成长回路

01完成任务

05形成持续投入

正在探索的延伸：把好友与访客放入 Character，让朋友访问小屋、留下徽记或小礼物，使成长成果被温和地看见，而不是发展成高压力的信息流社交。

03 · DESIGN DECISIONS

四个关键设计决策

放置互动式首页

首页不是数据面板，而是与现实任务同步的生活场景。角色会阅读、专注或休息，让用户回来时看到时间和行动留下的变化。

成长与装扮经济

完成任务获得 EXP 与积分，角色升级后解锁人物道具；积分还可在公会商城购买小屋装饰，把抽象进度转化为可拥有的空间。

主动生成日记

完成三项任务后解锁日报，由用户选择英雄旅程、安静反思或幻想编年史，而不是被系统自动打断。

故事与真实双重记录

Adventure 保留想象力与情绪，True Record 保留真实行动，使故事化不会牺牲任务工具的可信度。

04 · ITERATION

原型中的真实迭代

这些改动来自持续操作原型时发现的问题，而不是为了补齐一套标准 UX 流程。

CHRONICLE

将卡片交互拆成 Adventure 与 True Record，减少信息混杂。

REPORT FLOW

重新设计日报选择层级，并修正小屏幕上的内容溢出。

CHARACTER

反复校正角色比例、动作和场景关系，让“正在生活”而非“贴图”成立。

LOCALIZATION

补全中、日、英三语界面，并持续调整日语表达与信息长度。

05 · FINAL DESIGN

四个页面，一条完整体验

PAGE 01

Home & Dream Vault

在放置场景中查看今日任务、角色状态与尚未执行的愿望。

PAGE 02

Quest Hall

创建和整理任务，把现实事项转译为清晰但具有世界观的任务。

PAGE 03

Chronicle

回看每日生成的冒险，以及与之对应的真实记录。

PAGE 04

Character

管理角色、叙事风格、界面语言与 Chronicle 偏好。

07 · REFLECTION

设计反思

Guild Log 让我意识到，游戏化不是增加积分、等级或装饰，而是重新设计行动之后得到的意义。真正重要的不是“像游戏”，而是实用性、作者性和情绪回报之间的平衡。下一阶段，我会在真实测试后收紧机制，并继续探索周记、月度章节与更长期的角色成长。
